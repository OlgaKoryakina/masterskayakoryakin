## Что уже работает

Админ-панель `/admin` существует и закрыта ролью `admin`. Уже есть:
- Управление товарами (фото и видео сразу несколькими файлами с компьютера)
- Заявки из корзины и индивидуальные со сменой статуса
- Редактирование текстов сайта

План добавляет только то, что вы выбрали.

---

## 1. Заказы: расширенные статусы и фильтры

**Новые статусы:** Новая → Подтверждена → В производстве → Готова → Отправлена → Доставлена → Отменена

- Миграция БД: расширить enum `request_status` новыми значениями. Существующие заявки сохранятся, старые значения (`new`, `in_progress`, `closed`) остаются совместимы — `closed` будет отображаться как «Доставлена» в UI, остальные мапятся 1:1.
- Селектор статуса в карточке заявки получит все 7 значений с цветовой меткой.

**Фильтры и поиск на `/admin/requests`:**
- Поиск по имени, телефону, мессенджеру
- Фильтр по статусу (мульти-выбор chip-ами)
- Фильтр по диапазону дат (от / до)
- Сортировка: новые сверху / старые сверху
- Счётчики у вкладок «Из корзины» и «Индивидуальные» учитывают активный фильтр

**Карточка заявки — больше деталей:**
- Кнопки «Позвонить» (`tel:`) и «Написать в WhatsApp/Telegram» (по полю `messenger` и `phone`)
- Для заявок из корзины: фото и slug каждого товара (берём из `snapshot` + ссылка на `/product/$slug`), итоговая сумма
- Для индивидуальных: превью референсов из приватного бакета `custom-references` через signed URL
- Кнопка «Удалить» (есть RLS policy `requests_admin_delete`)

## 2. Товары: удобнее загрузка медиа

Заменяем простой `<input type="file">` на полноценный медиа-менеджер внутри редактора товара:

- **Drag-and-drop зона** для загрузки файлов мышью прямо с рабочего стола
- **Прогресс загрузки** для каждого файла + индикация ошибок
- **Раздельные секции** «Фото» и «Видео» с превью
- **Сортировка перетаскиванием** (dnd-kit) — первое фото становится обложкой; индикатор «Обложка» на первом элементе
- **Кнопка «Сделать обложкой»** на любом фото — поднимает его наверх
- **Удаление файла из хранилища** при удалении из карточки (а не только из массива URL)
- **Видео по ссылке:** дополнительное поле «Добавить ссылку YouTube / Vimeo». В БД храним в том же массиве `videos` — отличаем загруженные файлы от ссылок по URL. На сайте: файл → `<video>`, ссылка YouTube/Vimeo → `<iframe>` встроенного плеера.
- Лимит размера видеофайла — 50 МБ (предупреждение в UI).

## Технические детали

**Миграция (одна):**
```sql
ALTER TYPE request_status ADD VALUE 'confirmed';
ALTER TYPE request_status ADD VALUE 'in_production';
ALTER TYPE request_status ADD VALUE 'ready';
ALTER TYPE request_status ADD VALUE 'shipped';
ALTER TYPE request_status ADD VALUE 'delivered';
ALTER TYPE request_status ADD VALUE 'cancelled';
```
Старые `in_progress` оставляем — будет означать «В производстве» в UI-маппинге.

**Новые файлы:**
- `src/components/admin/MediaManager.tsx` — drag-and-drop + сортировка + прогресс + embed-ссылки
- `src/components/admin/RequestFilters.tsx` — панель фильтров и поиск
- `src/lib/request-status.ts` — словарь статус → русский лейбл + цвет
- `src/lib/video-embed.ts` — определение типа видео (file / youtube / vimeo) + получение embed URL

**Изменения:**
- `src/routes/admin.requests.tsx` — подключить фильтры, кнопки связи, превью референсов, удаление
- `src/routes/admin.products.tsx` — заменить блок «Фото и видео» на `<MediaManager>`
- `src/components/site/ProductMedia.tsx` (или место, где сейчас рендерится галерея на странице товара) — поддержать embed-видео

**Зависимости:**
- `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities` для перетаскивания

Что НЕ трогаем: схему `products`, текущие RLS-политики, публичный сайт (только рендер видео-embed добавится).
